Intent

01

Learning to build a real ANC system

After studying and simulating active noise control in my ANC Practice Library, I started this prototype to carry that work into hardware. It is preliminary work for my thesis: a way to develop the practical experience needed for a more ambitious research project.

The target is a single-channel feedforward demonstrator. A reference microphone senses the disturbance, an error microphone monitors the target location, and an adaptive controller generates the loudspeaker signal. Building it means making the algorithm work within the limits of audio timing, acoustic propagation, memory, and processing time.

Audio architecture

02

48 kHz audio with an 8 kHz controller

Acquisition
Two INMP441 MEMS microphonesReference and error channels share the audio clock with the DAC. Acquisition and playback stay at 48 kHz through I2S and circular DMA.
Processing
NUCLEO-F446RE · STM32F446REEach DMA half-buffer holds 48 samples per channel. Conversion produces eight samples per channel for FxLMS, while the block interval stays at 1 ms.
Output
PCM5102 DAC, TDA2030 amplifier, and control loudspeakerThe controller output is interpolated and filtered before returning to PCM24 at 48 kHz for the DAC.

Sample-rate conversion

  1. PCM24 input48 kHz · REF + ERR
  2. Float + antialiasLow-pass filtering
  3. Decimate ÷648 → 8 samples
  4. FxLMS8 kHz · 8 samples
  5. Interpolate ×68 → 48 samples
  6. ReconstructLow-pass filtering
  7. PCM24 output48 kHz · DAC

Scroll signal chain horizontally →

The conversion filters are eighth-order Chebyshev II designs, each implemented as four cascaded biquads in transposed direct form II. REF, ERR, and output have independent filter states. The converter passed numerical comparison against a reference implementation.

Engineering decisions

03

Moving the controller to the time domain

Reducing the sample rate lowered the workload, but the earlier FFT-based implementation was still too costly. I then moved filtering and adaptation entirely to the time domain.

G · Secondary path

Filter the reference for adaptation

The model of the control speaker’s path to ERR is applied with the CMSIS-DSP FIR implementation, producing the filtered reference used to update the controller.

F · Acoustic feedback

Compensate the reference signal

A custom time-domain filter models the control speaker’s contribution at REF, allowing that contribution to be removed from the measured reference.

W · Adaptive controller

Generate and adapt the output

W is applied in time. Its coefficients are updated through direct block correlation between the error and filtered reference, using a history of samples.

A standalone firmware project

Simplifying the implementation

The new ANC project is separate from the preserved I2S_USB version. USB, USB Audio, HAL, and FFT dependencies were removed. Clock, I2S, and DMA configuration use peripheral registers. PASSTHROUGH, DAC_TONE, and ANC modes are selected in appConfig.h.

Processing results

04

Finding a configuration within the block budget

Benchmarks on the STM32, compiled with -O3, include the complete sample-rate conversion chain. Comparing implementations with the same synthetic G30/F441/W471 profile shows the effect of changing the controller architecture.

What this benchmark establishes

This is an isolated processing result with synthetic coefficients, interrupts masked, and audio and DMA inactive. It identifies a candidate that fits the calculation budget. Sustained execution with live audio and the measured models still needs to be tested.

The 0.888 ms figure is calculation time, not total system latency or a formal worst-case execution-time guarantee.

Models and validation

05

Preparing the acoustic test

Measured paths in the firmware

The geometry was rebuilt and the paths to REF and ERR were measured again with REW and a loopback timing reference. A new electrical loopback measurement corrected the Focusrite gain scale at its current settings.

The 48 kHz impulse responses were converted offline to equivalent 8 kHz models, including the firmware’s conversion filters. Time origin and polarity were preserved, and differences in sweep level were compensated.

The active model windows are G[0:64] and F[0:512], with 576 coefficients for W. Longer source tables are retained so the cuts can be changed in CubeIDE.

Current validation status

Acoustic cancellation is the next stage

Sample-rate conversion, the time-domain controller, and measured-model loading are implemented. Basic DAC and both microphone passthrough tests worked on hardware. A clean checkout builds in Debug and Release, and the linked model coefficients were checked.

The new measured-model configuration has not yet been flashed for a cancellation test. Acoustic cancellation on the complete hardware system remains unvalidated.

Next hardware checks

  1. Verify the adaptation sign and the models’ timing equivalence at the controller’s physical ports.
  2. Measure sustained processing with audio and DMA active.
  3. Begin physical cancellation tests in the 100–500 Hz band.
